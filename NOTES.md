# ProDoctorov slot-watcher — заметки

## Ключевой тейк (подтверждено 2026-07-01)

**API `slots_bulk` доступен всегда и не зависит от подписки клиники.**

- Клиника на тарифе **«Лайт»** → на публичной странице врача
  (`/moskva/vrach/975987-hafez/`) **нет виджета «Выбрать дату и время»**,
  и слот **нельзя забронировать онлайн** — только по телефону.
- При этом backend-API
  `POST https://prodoctorov.ru/ajax/schedule/slots_bulk/`
  **возвращает реальное расписание врача, даже когда виджет выключен.**
- Доказательство: 2026-07-01 виджет был выключен, а API вернул свободный слот
  `lpu 70382 (корп. 1501) → 2026-07-30 08:00 free:true`.

**Вывод:** тариф/подписка управляют только кнопкой записи на сайте, а НЕ доступностью
API. Раннее предположение «интеграция включается/выключается вместе с подпиской» —
**неверно**. API — надёжный сигнал, который работает постоянно и ловит освободившиеся
по отмене слоты, невидимые на сайте.

## Антибот ServicePipe (13.09.2026)

11.09.2026 в 00:53 prodoctorov закрылся антиботом **ServicePipe**: вместо страницы
приходит HTML-заглушка на 1803 байта с JS-челленджем
(`servicepipe.tech/loaders/….js`). Watcher два дня писал в лог три разных
сообщения — «сайт изменил вёрстку», `invalid character '<'`, «csrftoken не
найден» — но причина была одна: заглушка попадала в три разных парсера.

**Челлендж решать не нужно — достаточно под него не попадать.**

- ServicePipe подменяет заглушкой только **навигационные** запросы
  (`Sec-Fetch-Dest: document`). Тот же адрес, запрошенный как **XHR**
  (`X-Requested-With: XMLHttpRequest` + `Sec-Fetch-Dest: empty`), отдаётся
  целиком. Замер: навигационные заголовки — 0/3, XHR-заголовки — 3/3.
- **`Referer` обязателен.** Без него заглушка приходит даже на XHR (0/3 против
  3/3). Подойдёт любой адрес того же сайта.
- **uTLS обязателен.** С обычным Go-TLS заглушка приходит при любых заголовках —
  ServicePipe режет по JA3 и на ajax-эндпоинте тоже.
- **Браузерный User-Agent обязателен**: без него `slots_bulk` отдаёт 403.
- **csrf-токен и cookie для `slots_bulk` НЕ нужны** — 8 из 8 запросов с пустым
  cookie jar и без `X-CSRFToken` вернули настоящий JSON. Старый код ради токена
  делал GET страницы перед каждым POST — именно этот GET и упирался в заглушку.

Решать челлендж «по-честному» непрактично: 368 КБ обфусцированного JS с
ротацией имени файла, отпечаток собирается в blob-воркерах (WebGL, canvas,
шрифты), а перенос готовых cookie из Chrome в Go-клиент не работает — сессия
привязана к отпечатку соединения (проверено четырьмя вариантами переноса).

## Практика
- Записываться на пойманный слот — **по телефону** клиники (онлайн-кнопки не будет,
  пока клиника не вернёт интеграцию).
- `csrftoken` не нужен: `slots_bulk` отвечает по одним браузерным заголовкам
  (см. раздел про ServicePipe выше).
- Неофициальный API: формат могут поменять; опрос раз в 20 мин — щадящий режим.
- Сигнал работает только пока сервер онлайн (сейчас — Mac, не во сне).
